# AI GM / Tabletop Kernel — V3.17 Handoff

Continue from `tabletop_kernel_v3_17/` (V3.16.1 foundation). Read `GAME_CLOCK_AND_FAST_FORWARD_V3_17.md` and `CHANGES_V3_17.md`, plus previous `AI_GM_HANDOFF_V3_16_1.md` for wall/phase movement.

**Architecture:** Deterministic Pathfinder 1e mechanics calculator subordinate to an independent creative AI GM. It does not decide tactics, character choices, travel, rest, watches or narration. GM-authorized exceptions and world effects are declarative. Player character data and statblock totals are imported. Existing attack, maneuver, riders, armor, defense, visibility and path systems remain.

**New V3.17:** `time_engine.mjs` defines `TimeGame extends DefenseGame`. `scenarios.mjs` instantiates `TimeGame`. `worldRounds` remains canonical elapsed time in 6-second increments, with `clockOffsetRounds` used for Day N HH:MM:SS calendar display. GM-only operations: `gm_get_game_clock`, `gm_set_game_clock`, `gm_advance_time`, `gm_advance_to_event`, `gm_schedule_time_event`, `gm_cancel_time_event`, `gm_acknowledge_time_event`. The source code is bundled into offline `index.html` and `tests.html` using `build_demos.py`, with the `TIME_ENGINE` placeholder after `DEFENSE` and before `SCENARIOS`.

**Event processing:** Rather than iterating through every six-second combat round, advance to the next due timestamp. Expire tracked timed effects/conditions and temp HP, process poison/disease/DOT ticks, resolve 24-hour negative-level saves, and return explicit GM events. A scheduled event requiring GM input pauses Fast Forward and returns remaining time; acknowledgement by the AI GM permits resuming. The calculator never invents activities or resting benefits. Pending actions block time advancement. Same-instant chronological priority is documented. Clock, event queue and decisions live in snapshot state; undo restores them.

**Validation:** `time_engine_tests.mjs` checks core calendar, atomic errors, event scheduling/acknowledgment, interval precision, ongoing effects, poisoned targets, recovery, temp HP, no implicit rest and undo. `test_browser_v3_17.py` checks the offline controls. Existing 24 Node suites and browser tests V3.10–V3.16.1 are expected regression coverage; rerun before next release. Run `python build_demos.py` after source or UI changes. Browser test harness uses `/usr/bin/chromium`.

**Limits/future:** Six-second clock resolution; only established timing rules are automatic; some effect `onEnd` custom callbacks remain event-trigger-specific; no arbitrary real-world calendaring; no automatic activities or passive rest/heal; dense event processing safety cap. User anticipates a later *map system redesign* to allow line walls between squares, partial-square walls/cover, and squeezing. Do not add tactical pathfinding or AI tactics to the calculator. Previous ordinary attack gaps (ranged/thrown attacks, nonlethal, size-based dice) also remain candidates. Next work should be selected based on user direction; do not silently assume a full time-based rest model.
